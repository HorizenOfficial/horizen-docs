# Horizen — Quick Reference for AI Coding Assistants

> Horizen's developer documentation covers three areas: **Vela**, a confidential execution coprocessor by Horizen Labs; the **ZEN token migration** to Base; and **Horizen DAO governance**. The standalone Horizen Chain (an EVM L3) has been wound down — its network, bridging, deployment, and chain-specific tutorial pages have been retired and now redirect into the sections below.
>
> Vela runs your application logic as WebAssembly (WASM, compiled from Go with TinyGo) inside a Trusted Execution Environment (AWS Nitro Enclave), where data is isolated from the host, the cloud provider, and the operator, and application state is encrypted at rest (AES-256). Smart contracts are both the entrypoint (submit an encrypted request, lock funds) and the exitpoint (a cryptographically attested result settles funds and can fire on-chain events). Every result is signed by the attested enclave and verified on-chain, so contracts and autonomous agents can verify, gate, and settle on the outcome without trusting any operator in between. Authorized auditors can request encrypted compliance reports from the TEE without exposing other users' data; authorization is managed on-chain via the `AuthorityRegistry` contract. Vela is chain-agnostic and live (gated / early access) on Base mainnet and Base Sepolia; develop locally via Docker with a software-emulated TEE (no AWS account required).

## Vela (Confidential Execution — TEE coprocessor by Horizen Labs)

- [What is Vela?](https://docs.horizen.io/vela/introduction): TEE-based confidential execution solution by Horizen Labs — AWS Nitro Enclaves, hardware attestation, signed results verified on-chain, and encrypted compliance reports for authorized auditors via the `AuthorityRegistry` contract · chain-agnostic coprocessor · https://vela.horizenlabs.io/
- [Prerequisites](https://docs.horizen.io/vela/getting-started/prerequisites): Required tools and setup before starting Vela development
- [Local Environment Setup](https://docs.horizen.io/vela/getting-started/local-environment-setup): Docker-based local dev environment with a software-emulated TEE (`NoAttestationTeeAuthenticator`) · local chain ID 31337 · no AWS account required

- [Roadmap — What's Available & What's Coming](https://docs.horizen.io/vela/roadmap): Available today: local Docker dev, Base Sepolia, and Base mainnet (gated / early access) · ERC-20 tokens, compliance reports, and multi-app support shipped · Coming next: self-service testnet deployment

## ZEN Token Migration

> **Migration completed July 23, 2025.** ZEN balances from both the old Horizen mainchain (ZEND) and the EON EVM chain have been migrated to a ZEN ERC-20 contract on Base. **There is no deadline to claim.**

- [Migration Overview](https://docs.horizen.io/migration/overview): What was migrated and how — EON balances auto-migrated to the same address; ZEND mainchain balances require a manual claim because UTXO addresses don't map automatically to Ethereum addresses
- [Claiming ZEND Mainchain ZEN](https://docs.horizen.io/migration/claiming-zen): Manual claim process — need ETH on Base, sign a message with your old Horizen wallet key, call `claimP2PKH` / `claimP2SH` / `claimDirect` on the `ZENDBackupVault` contract · Official UI: https://www.horizen.io/zenclaim
- [Step-by-step Claim Instructions](https://docs.horizen.io/migration/mainnet-migration-instructions/mainnet-claim): Full walkthrough — get ETH on Base, create a signature with your old wallet, submit the claim · Sphere Wallet, Ledger, other-wallet, and CLI paths covered
- [Smart Contracts](https://docs.horizen.io/migration/smart-contracts): ZEN ERC-20 on Base: `0xf43eB8De897Fbc7F2502483B2Bef7Bb9EA179229` · `ZENDBackupVault` (manual claim): `0x1Ee188bDf19eBF04B73Ab6FFcec2a864cd4774F2` · `EONBackupVault` (auto-mint): `0x1Cc689233837A0b96e1f176d49FC08462f70C47F` · audited by Cantina and Halborn
- [Migration Tools](https://docs.horizen.io/migration/migration-tools): CLI tool and signing utilities for users who need to sign without a GUI wallet
- [Troubleshooting & FAQ](https://docs.horizen.io/migration/troubleshooting): Common claim issues — wrong Sphere version, signature format errors, insufficient ETH for gas
